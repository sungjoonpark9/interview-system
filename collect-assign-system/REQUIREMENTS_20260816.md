# 인터뷰 예약 앱 요구사항 정리

기준일: 2026-08-16
상태: TFT 검토 내용을 반영한 목업 기준

## 1. 기본 원칙

- 앱은 `개인정보 없는 앱`보다 **개인정보 최소화·분리형 앱**으로 설명한다.
- 앱에는 이름·회중·연락처·이메일·건강 정보·면접 결과를 저장하지 않는다.
- 예약코드는 원본 개인정보를 암호화한 문자열이 아니라, 원본과 별도 보관되는 무작위 식별자다.
- 예약코드와 실제 사람의 연결표는 앱 밖의 승인된 환경에서 별도 관리한다.
- 자원봉사자 면접은 **개별 면접**이 원칙이다. 부부·가족 동반 면접 기능은 제공하지 않는다.
- 자원봉사자와 인터뷰어의 정보 수집은 병행하며, 관리자가 배정 단계에서 연결한다.

## 2. 사용자와 권한

### 자원봉사자 — 모바일 중심

- 예약코드로 접속
- 날짜별 오전·오후 단위로 가능한 시간 선택
- 같은 날 오전과 오후 모두 선택 가능
- 최대 7일 범위 선택
- 마감 전 제출 내용 조회·수정
- 확정된 인터뷰 일정 확인
- FAQ 확인
- 정형화된 문의 접수 및 예약코드로 답변 확인

### 인터뷰어 — 모바일 중심

- 인터뷰어 코드로 접속
- 가능한 시간대 복수 선택
- 시간대별 처리 가능 인원 입력
- 제출 내용 조회·수정
- 배정 일정과 처리 인원 확인
- 기존 설문으로 수집한 1차 인터뷰어 가용시간을 관리자가 일괄 반입 가능

### 콜센터 자원봉사자

- FAQ 검색
- 접수된 문의 확인
- 문의 답변 작성
- `접수 → 처리 중 → 답변 완료` 상태 관리
- 전체 자원봉사자 명단·연결표·배정표·예약코드 관리·결과 다운로드 권한 없음
- 개인정보·민감정보가 포함될 가능성에 대비한 비밀 유지 교육 및 서약 여부는 정책으로 결정

### VM 운영 관리자 — PC 중심

- 자원봉사자·인터뷰어 제출 현황 확인
- 기존 인터뷰어 가용시간 자료 반입
- 시간대별 정원 자동 계산 및 필요 시 조정
- 자동 배정 실행 및 수동 조정
- 예약코드 발급·중지·재발급
- 문의 처리 현황과 FAQ 관리
- 운영 결과 CSV 다운로드

### 시스템 관리자

- 계정·권한·환경설정·배포·장애·감사로그·백업·삭제 관리
- 운영 데이터의 일반 업무 열람은 최소화

## 3. 시간 선택·배정 규칙

- 자원봉사자는 개별 시간을 반복 클릭하지 않고 날짜별 `오전`·`오후`를 선택한다.
- 최소 선택 수는 두지 않되 가능한 범위를 최대한 많이 선택하도록 안내한다.
- 인터뷰어는 각 시간대별 처리 가능 인원을 제출한다.
- 관리 정원은 인터뷰어 가용시간과 처리 가능 인원을 기반으로 자동 계산한다.
- 자동 배정을 기본으로 하고 관리자가 수동 조정할 수 있다.
- 초기 자동 배정 목표는 계산 정원의 70%로 두되 운영값으로 조정 가능하게 한다.
- 제출 마감 전에는 동일 코드로 조회·수정하고, 배정 확정 후에는 문의를 통해 변경 요청한다.

## 4. 문의·FAQ 원칙

- 문의 전에 FAQ를 먼저 제시한다.
- 문의 유형은 정형 선택을 우선하고 자유 입력은 최소화한다.
- 이름·회중·전화번호·이메일·건강 정보 등 개인정보·민감정보 입력 금지를 명확히 안내한다.
- 답변은 앱 안에서 예약코드로 확인한다.
- 외부 문자에는 답변 내용 대신 `답변 등록 사실과 앱 주소`만 안내한다.
- 문의 데이터에는 예약코드·유형·내용·상태·답변·시각만 저장한다.
- 보존·삭제 기간은 운영 정책으로 확정한다.

## 5. 현재 목업의 한계

- 브라우저 `localStorage`를 이용하므로 같은 브라우저 안에서만 데이터가 공유된다.
- 실제 인증·중앙 DB·문자 발송·암호화·감사로그·CSV 업로드 검증은 구현하지 않은 화면 검토용 목업이다.
- 실제 개발 전 저장환경, API, 보안, 운영주체와 승인 범위를 별도로 확정해야 한다.

## 6. 아직 정책·시스템 결정이 필요한 항목

- 실제 저장환경과 API 운영 주체
- 예약코드 발급·재발급·회수·만료 규칙
- 자원봉사자 제출 마감과 배정 확정 시점
- 자동 배정 목표 비율의 초기값과 조정 권한
- 문의·답변·접속·변경 기록의 보존 및 삭제 기간
- 개인정보로 보이는 자유 입력을 탐지·가림 처리할 수준
- 답변 완료 문자와 긴급 공지를 발송할 승인 채널 및 담당자

## 10. 역할별 소통 기능

- 도움말 메뉴는 `공지사항 / 자주 묻는 질문 / 문의하기`로 구성한다.
- 자원봉사자는 공통 공지와 자원봉사자 공지·FAQ·문의 유형을 확인한다.
- 인터뷰어는 공통 공지와 인터뷰어 공지·FAQ·문의 유형을 확인한다.
- 공지는 VM 운영 관리자 또는 시스템 관리자만 등록·수정·삭제한다.
- 콜센터 자원봉사자는 문의 처리에 필요한 공지와 FAQ를 조회하되 공지 관리 권한은 갖지 않는다.
- 등록 후 7일 이내 공지에는 `N`을 표시한다. 7일이 지나면 공지는 유지하되 `N`만 자동으로 사라진다.
- 문의는 로그인한 예약코드 또는 인터뷰어 코드에 자동 연결하여 코드를 다시 입력하지 않게 한다.

## 11. 로그인 이후 화면과 역할별 메뉴

- 자원봉사자와 인터뷰어는 최초 로그인 때 확인한 코드를 가능시간 제출 화면에서 다시 입력하지 않는다.
- 로그인한 코드로 기존 제출 내용을 자동 조회하고, 다른 코드로 바꾸려면 로그아웃 후 다시 로그인한다.
- 자원봉사자 메뉴는 `자원봉사자 / 도움말`, 인터뷰어 메뉴는 `인터뷰어 / 도움말`으로 제한한다.
- 콜센터 자원봉사자 메뉴는 `콜센터 / 도움말`으로 제한하며, 소통에는 `공지사항 / FAQ`만 표시한다. 문의 답변은 콜센터 화면에서 처리한다.
- VM 운영 관리자 메뉴는 우선 `관리자 / 도움말`으로 제한한다. PC 중심 관리자 대시보드는 별도 설계한다.
- 시스템 관리자는 운영 점검을 위해 `관리자 / 콜센터 / 도움말`에 접근할 수 있다.
- 기존 1차 인터뷰어 설문 파일의 열 매핑·검증·중복 처리 기준


## 2026-08-22 목업 피드백 반영
- 홈 화면에 `공지사항 / 자주 묻는 질문 / 문의하기`를 동일 수준의 진입점으로 노출한다.
- 하단 `소통` 명칭은 `도움말`로 변경한다.
- 사용자에게 보이는 기능 명칭은 `문의`, `문의하기`, `문의함`으로 통일하고 `콜센터`는 담당 역할명으로만 사용한다.
- 공지사항과 FAQ는 `전체 / 자원봉사자 / 인터뷰어 / 콜센터 / VM 관리자 / 시스템 관리자` 대상별로 등록·필터링할 수 있도록 한다.


## 2026-08-22 로그인 전·후 홈 분리
- 로그인 전 홈은 역할 선택 화면으로 사용한다.
- 로그인 후 홈에서는 `누구신가요?` 및 다른 역할 선택 카드를 표시하지 않는다.
- 로그인 후 홈은 현재 역할에 필요한 대표 기능과 도움말 진입점만 보여 주는 역할별 대시보드로 사용한다.
- 로그인 상태에서도 `홈` 버튼으로 역할별 홈에 돌아갈 수 있으며 로그아웃은 별도 동작으로 유지한다.
- 하단 메뉴는 기존 권한 규칙에 따라 로그인한 역할에 필요한 메뉴만 표시한다.
