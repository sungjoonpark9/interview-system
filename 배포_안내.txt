[예약코드 방식 목업 배포 안내]

1. 이번 버전에서 바뀐 점
- 신청자는 이름·회중·전화번호·이메일 대신 VM부가 발급한 예약코드만 입력합니다.
- 인터뷰어도 이름·이메일 대신 인터뷰어 코드를 사용합니다.
- 관리자 화면에는 예약코드와 인터뷰어 코드가 일부 가려져 표시됩니다.
- 문의 화면에도 예약코드만 입력하며, 문의 내용에는 개인정보를 쓰지 않도록 안내합니다.
- 기존 브라우저 데모 데이터와 섞이지 않도록 저장소 키를 새 버전으로 변경했습니다.

2. 꼭 알아둘 제한
- 현재 GitHub Pages 버전은 운영 구조를 확인하는 정적 목업입니다.
- 입력값은 인터넷 DB가 아니라 각 사용자의 브라우저 localStorage에만 저장됩니다.
- 따라서 A 사용자가 입력한 예약을 B 사용자의 관리자 화면에서 볼 수 없습니다.
- 실제 운영에는 승인된 내부 저장소/API 또는 별도 수집·취합 절차가 필요합니다.
- 예약코드는 이름·회중을 암호화해서 만들지 말고, 개인을 유추할 수 없는 무작위 값으로 발급해야 합니다.

3. 가장 쉬운 배포 방법 — GitHub Desktop 사용
① GitHub Desktop을 설치하고 GitHub 계정으로 로그인합니다.
② File > Clone repository에서 sungjoonpark9/interview-system 저장소를 선택합니다.
③ Repository > Show in Explorer를 눌러 로컬 저장소 폴더를 엽니다.
④ 이 ZIP을 풀고, 안의 파일과 폴더를 로컬 저장소에 그대로 덮어씁니다.
⑤ GitHub Desktop으로 돌아가 변경 파일 목록을 확인합니다.
⑥ Summary에 "예약코드 방식 목업 적용"을 입력하고 Commit to main을 누릅니다.
⑦ Push origin을 누릅니다.
⑧ 약 1~3분 뒤 아래 주소에서 새로고침합니다.
   https://sungjoonpark9.github.io/interview-system/collect-assign-system/app.html

4. 시연용 코드
- 신청자 예약코드 예: VM27-A7K9-P2Q4
- 인터뷰어 코드: INT-2027-01 또는 INT-2027-02
- VM 관리자 코드: VM-ADMIN-27

5. 배포 후 확인 순서
① 신청자 화면에서 예약코드와 가능 시간을 제출합니다.
② 로그아웃 후 인터뷰어 코드로 접속해 가능 시간을 제출합니다.
③ VM 관리자 코드로 접속해 관리자 화면에서 배정 실행을 누릅니다.
④ 예약코드가 일부 가려져 보이는지 확인합니다.
⑤ 다른 기기에서는 같은 데이터가 보이지 않는지 확인합니다. 이것은 현재 목업의 정상 동작입니다.

6. 보안 주의
- 채팅이나 공개 저장소에 GitHub Personal Access Token(PAT)을 올리지 마십시오.
- 이전에 공유된 PAT가 있다면 GitHub Settings > Developer settings > Personal access tokens에서 즉시 폐기하고 새로 발급하십시오.
- 이 목업을 그대로 실제 개인정보 처리 시스템으로 사용하면 안 됩니다.
